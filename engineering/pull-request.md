# IssueとPull Request

権限と公開の判断は[AI開発ポリシー](agent-policy.md)に従います。

## 粒度

- 1 Issue = 1目的、1 PR = 1責務。無関係な整形やリファクタリングを混ぜません。
- 300行・10ファイル以内が目安です。超過は警告とし、分割案か分割しない理由を記録します。
- baseとのmerge-baseからの追加＋削除行数と変更ファイル数で数えます。生成物・lockfileを別扱いにする場合も総量と除外対象を記録します。

## 提出とレビュー

検証と必要なCIを通して通常PRを提出し、次を本文に記載します。

- 目的、変更概要、関連Issue・依存関係（非公開情報は公開PRへ転載しない）。
- 検証のコマンド・手順、対象コミット、結果。未実行・CI未設定は理由を明記する。
- リスク、残る課題、人間の判断が必要な事項。
- dot経由の作業には識別行 `作業元: dot（AI支援）` を付ける。レビューへの返信にも同じ識別を付ける。

変更に応じてtest・lint・buildを実行し、文書はMarkdown・相対リンク・差分・秘密情報を確認します。
push後はhead SHAとCI結果を確認し、修正後は影響する検証を再実行します。
本人のレビューを反映して再レビューを依頼し、マージは人間の明示承認を待ちます。
PR提出だけでIssueを完了扱いにしません。
